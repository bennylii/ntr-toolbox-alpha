往队列喂一个文本 → 提取术语表：完整流程

对应 NTR ToolBox 里的「术语队列」+「AI提取术语表」；括号里是代码里的名字，方便对照调试日志（[NTR-G] 前缀）
主流程 只读 / 落库 失败与分支 人工关卡

0 · 入队

加进队列 面板「加入当前页 / 加入收藏页 / 加入本地书架」，或「AI提取术语表」在「任务方式=加入队列」时点一下模块 addJobs(targets, extractSettings()) 把「目标 + 设置快照」写进 IndexedDB ntr-glossary/jobs（任务持久化，刷新/关页面都还在）
哪些设置现在固定、哪些跟着你改 入队时快照：原文语言 · 分块字数 · 最大轮数 · 行数上限 · 输出上限 · 翻译器（含临时端点/模型/Key） 每次开跑实时读：并发 · RPM · 逾时（jobRuntime()，改设置影响下一个任务/下次续跑）
▼

1 · 开跑

队列点「开始/续跑」或刷新页面 2.5s 后自动续跑（有 pending 且「自动续跑」开着时） 任务置 running → 日志「任务开始」→ jobRuntime() 取实时参数
解析翻译器 resolveWorkers 工作区 GPT 翻译器（下拉选的或全部轮换）／临时端点三元组；一个都没有 → 任务失败并写清原因
▼
抓正文（全程只读）loadGlossarySourceText
  • 网页小说：GET /api/novel/{provider}/{id} 拿标题 → /file?mode=jp 下载 txt
  • 文库：GET /api/wenku/{id} → volumeJp[] → 每卷 translate-v2/gpt/{卷} 拿 toc → chapter-task/{章} 的 paragraphJp[] 拼正文
  • 本地卷：站点 IDB volumes@2 里逐章读
文库抓取进度会写回 job.progress.sync（面板「备注」列实时显示）
▼
行级清洗 splitLines → languageFilter(原文语言) → ruleFilter(资源名/纯符号行…) → 行数上限
空正文 过滤后 0 行 → 任务失败「正文为空」（换原文语言或换书）
▼

2 · 缺口计算：这次到底要跑哪些行

读分块缓存记录 jobChunkRecords IDB chunks 里键以 job:<任务id>/ 开头的记录，每条都带它覆盖过的正文行
多重集差 uncoveredLines 「这本书的行」减去「已成功块覆盖的行」→ 只把没覆盖过的行发出去（同一行出现多次也各自计数）
没有未覆盖行 → 直接置「待确认」，提示「没有未处理的正文行」，一个请求都不发。这就是「重试」按钮走的路：只补漏，不重跑。
缓存命名空间：整本跑用 job:<id>，补跑用 job:<id>/fill（补跑的块序号不再对应书里的位置，分开存避免错接）。
▼

3 · 轮次循环 runJob

每轮预算 roundBudget = max(200, 分块字数 ÷ 2^(第几轮−1))：第 1、2 轮同预算（瞬时失败原样再来一次），第 3 轮起才减半
分块 makeChunks 按预算切行（同时限制行数，避免短句挤爆），每块带原文文本
▼
并发 worker 抢块，每块依次过：
  1. 缓存命中？ 键 …/r<轮>/c<序号>，命中还要 linesMatch 核对行一致 → 直接复用（不重发、不计速）
  2. 限流闸门：令牌桶（并发/RPM）+ 全局冷却（被限流后的等待，停止键可打断）
  3. 选 worker：轮转 + 连续失败 2 次冷却 60s → POST {endpoint}/v1/chat/completions（温度 0，默认不发 max_tokens）
  4. 解析：剥 thinking → JSONLINE 逐行修复 → 条目（含 type/count 上下文）
成功 → 条目进内存、这些行记为已覆盖、写分块缓存（下次刷新/重试直接复用）； 失败（429 / 超时 / 空响应）→ 行退回待处理、块失败 +1、按上游要求进冷却。
轮末：没轮到的块（点了停止）的行也归还，然后带着剩下的行进下一轮；待处理为空或到「最大轮数」就收尾。
▼

4 · 后处理（零 token，postProcess）

清洗与投票
  1. 归一化（全角→半角 / 去振假名）
  2. 按标点拆分对齐（アリス・ローズ → 两条）
  3. 整句丢弃：src 含句读（。！？、等）直接扔 清洗计数
  4. 超长（>32 宽）/ 黑名单类型（其他）丢弃
  5. 同 src 投票选最佳 dst/type，去重
  6. 敬称合并：アルテさん 且 アルテ 也在表里 → 丢掉带敬称的（なるちゃん 这类整体昵称不动）清洗计数
回全文数次数 searchForContext 倒排索引（相邻字符对→行）算每个词的 count 与上下文；用长的先匹配、再打掩码防子串误配。 count=0 的条目丢掉；count 与上下文也是弹层「次数」列和排序的依据。
▼

5 · 合并 + 落库

和已有结果合并 补跑场景：新条目按 src 并进旧条目，然后按全文重算一遍 count（只拿补跑片段统计会偏小）
写回任务 put(job) progress（轮次/块数/已覆盖 X/Y 行/预计剩余）、entries、resultCount、state 全部进 IDB；面板与日志同步
停止 → 回到「待处理」（已跑过的块都在缓存里，点「开始/续跑」接着来）； 一条都没提取到 → 「失败」； 否则 → 「待确认」。 若开了队列设置「自动确认纯新增」且结果是纯新增（无冲突/相同）→ 跳过人工关卡直接写入并置「完成」。 完成通知会带上「清洗：整句 X 条 / 敬称 Y 条」。
▼

6 · 人工关卡：「待确认」（这一层才是你自己把关的地方）

「预览」= 预览-合并-diff
  • 行状态：新增 / 冲突 / 相同 / 仅已有；按类型、次数、搜索过滤，表头可排序
  • 「可疑」页签：过长 / 像短语 / 带敬称 / 含标点——只提示，不删、不动勾选
  • 次数过滤（默认藏低频词）、类型勾选、「筛选 ▾」面板
「再次筛选」= LLM 审计 把条目分批（300/批）发给模型，只打「建议删」标签（复合词不拆 / 称呼控制 / 整句过长…），筛完问你要不要取消勾选；按「并发」并行发批，进度在面板里刷新
▼
不满意就重来 「重试」= 接着跑，只补没覆盖到的正文行（走 /fill 缓存，不重发已成功的块）；
「重跑」= 整本重来一遍（成功的块仍然走缓存，结果整批重算）
「合并写入」writeGlossaryMerged ① 先给当前术语表存一份版本快照（每目标保留最近 20 个，可回滚）② 合并现有 → ③ PUT /api/…/glossary（本地卷写站点 IDB） 站点会提示已翻译章节过期，需要重新生成翻译才生效

7 · 出错时看哪里

开「调试日志」（AI提取术语表 设置里，默认关） 每个阶段的事件都会带时间戳写 Console 并留在内存里（WARN/ERROR 一直记，INFO 开了才记）
队列面板「导出日志」 下载一个 txt：请求耗时/worker/HTTP 码/冷却/缓存命中/轮次预算/清洗统计都在里面 —— 出问题直接导出丢给我就行
