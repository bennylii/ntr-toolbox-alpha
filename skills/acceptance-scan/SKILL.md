# 验收回扫（术语落地率）

对应工具：模块「验收回扫」。纯本地计算——读取术语表、整本原文、整本译文，字面匹配，不调用 LLM、不写站点。

## 四态语义

|状态|含义|进分母|
|---|---|---|
|已落地|原文出现该词，且译文里出现过对应译名|是|
|未落地|原文出现该词，但译文里找不到译名——**需要看的清单**|是|
|原文未见|整本原文都没出现该词（本卷不含 / ruby 变体未归一 / 提取时的误报）|否|
|不可检|原文出现，但译名过短或纯标点，字面检查不可靠（防止「他/了」级虚警）|否|

**落地率 = 已落地 ÷（已落地 + 未落地）**。它衡量的是术语表的实际效力，不是提取质量。

## 用法与边界

- 时机：术语表写入/更新后、整本翻译完成后各跑一次；「只看未落地」用于直接看问题清单；
- 译文来源：网页小说默认取站点 `gpt` 译文（可切换 sakura/baidu/youdao）；文库路径固定 gpt；
- 结果处置：未落地 → 对照上下文判断是「翻译没跟上」还是「条目本身该改/删」；勾选质变项后重译受影响章节，或走修句流程；
- **已知误报来源**：日文汉字与中文同形（译名恰为常见汉字词时可能在其他语境命中）；一章未译时整章计为未落地。看数不算数，看证据（报告里的「原文样例」与命中计数）再下结论。

## 反哺提取

- 大量「原文未见」→ 检查是否 ruby 变体没归一、或提取阶段的误报没清掉；
- 大量同类「未落地」→ 优先怀疑译名统一问题（词根/分支方案），而不是逐条翻译错误。

## 未落地清单的处置（修句）

未落地 ≠ 术语表有问题，也可能是译文没跟上。工具链里对应两个动作：

- **改表**：大量「原文未见」或同行成组未落地 → 回到提取/词根整理；译名整体不对 → 审核译名本身；
- **改译文**：「修句」模块以未落地清单为输入，让 LLM 在不动其他内容的前提下把指定译名落进译文，经审核面板逐段确认后**写回站点**（直接更新对应翻译器的字段，并且要求段落数与章节一致、术语表版本为当前版本）。

写回前的纪律：确认站点上没有正在跑的翻译任务（避免互相覆盖）；写回后重跑一次验收回扫，确认落地率真的上去了。
