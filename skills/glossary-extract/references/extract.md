# 提取流程：双通道 + 种子循环

## 总体结构

```
语言/规则过滤 → 程序通道探查（零成本，守门）→ LLM 分块提取（种子循环）
→ 本地归并（归一化/变体合并/敬称处理）→ 人工复核低置信项 → 写入（待确认 → 并入）
→ 定向补漏（种子轮）→ 验收回扫 → 译文反推补漏
```

原则：**能程序化判定的绝不问模型；问模型的每一次都要有具体调查目标。**

## 程序通道（守门员）

先做零成本探查，产出候选并**跳过没有信号的文本块**（省请求）：

- 连续片假名片段统计（日文场景的人名/外来语金矿）；
- 姓氏/名字 + 称谓共现（さん/様/くん/ちゃん/先生 等）；
- 书名号、引号内的高频专名；
- ruby 注音里的假名（往往就是人名读法）；
- 词频异常值（显著高于同分布的专名候选）。

程序通道的候选与 LLM 候选合并后统一去重。

## LLM 分块提取

- **分散采样**：从至少 3 个不连续的内容区域取块，避免只在开头几章打转；
- 块大小与重叠：按工具设置（默认 3000 字），相邻块保留少量重叠；
- 输出协议：JSONLINE（`{"src","dst","type"}`），引擎已有解析与自修复；
- 温度低（0–0.3），提示词要求"遇到不确定的候选也报出来，由后续核实裁决"。

## 种子循环（提高召回的关键）

一次分块提取跑完不等于结束。工具里的「种子补漏」就是这一机制的落地版：

- **种子来源（只收真实出现在正文里的模式）**：敬称条目的裸名、裸名在正文中实际出现的敬称写法、片假名条目的平假名写法、未收录的片假名信号串（按频次）；
- **定向轮**：主轮收敛后，按种子把相关行聚成定向块（同一行只发一次请求），focus 随块进入提示词（"定向补漏"段），要求「不编造译文、没有独立收录价值的不输出」；
- **上限与失败语义**：≤6 块、每种子 ≤40 行；补漏失败不回流待处理、不阻塞任务完成（尽力而为）；
- **可关**：「AI提取术语表」的「种子补漏」设置；
- 断点续跑：种子由"提取结果 + 已处理行"确定性重算，配合分块缓存不重复请求。

需要更彻底的调查（如跨章节核对某角色的家族归属）时，按种子账本手工组织定向请求；自动化版本只覆盖上述四类模式。

## 本地归并（写库前）

- 归一化：NFC + 全半角 + 半角片假名折叠（引擎 `normalize`）；
- ruby 清洗（引擎 `cleanRuby`）；
- 同 src 去重（保留多数投票胜出的 dst）；
- 敬称处理：裸名也在表里时丢掉带敬称条目（除非裸名不成立）；
- 整句/含句读的条目直接丢弃（计数进「清洗」统计）。

## 收尾

- 写入走「预览 → 待确认 → 并入」，并保留快照（可回滚）；
- 写入后跑一次**验收回扫**（见 acceptance-scan 技能），确认新条目在译文里真实落地；
- 未落地清单 → 人工判断：是翻译没跟上（修句/重译），还是条目本身有问题（改/删）；
- **译文反推**（模块）：在已翻译的小说上，用 jp-zh 对齐对反推未收录术语的译名建议
  （同一原文词反复出现时，与它共现且高特异性的汉字片段）。零 LLM 成本、只是启发式建议，
  误报高于提取——采纳前必须核对样例。
