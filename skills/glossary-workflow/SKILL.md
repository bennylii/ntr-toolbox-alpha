# 术语表工作流（NTR Daemon）

## 何时用
- 用户要"整理/生成/更新某本书的术语表"，或问"这个译名统一了吗"；
- 质检报告里出现 `GLOSSARY`（术语未落地）需要定位原因；
- 需要导入外部术语表（LG JSON / KWG 输出）或回滚到某个快照。

## 先看事实（只读）
1. `list_books` → 找到目标书的 key；`book_status` 看术语表条数、快照数、未决提案。
2. `read_book { book, offset, limit }` 分窗口读原文，确认候选词是否是**多次出现的专有名词**；
3. `read_translations { book }` 抽查现有译文里该词怎么翻的；
4. `list_snapshots` / `list_proposals` 看历史写入与待审项。

## 写入门槛（站点规范，不可绕过）
- 只收**专有名词与固定译名**（人名/地名/组织/物品/技能等），且原文出现 ≥2 次；
- 不收：普通名词、称呼/敬称控制、整句、复合词硬拆；备注用 `译名 #简短标签`；
- **绝不改动原文侧**（改原文会被站点拒绝且属滥用）；
- 每条都要有原文行证据；不确定的走提案（proposal），不要直接写。

## 写入路径
- 术语新增/更新走统一入口（快照 → 全量替换 → 回读校验）；写入前会请求用户审批；
- 被拒绝时不要换措辞重试；改成把条目整理成提案或给出建议；
- 回滚同理：先展示快照 diff，获批后恢复。

## 反例（不要做）
- "把 さん 统一翻译成小姐"（称呼控制）；
- 为单次出现的词造术语；
- 因为方便就整体重写术语表（覆盖他人条目）。
