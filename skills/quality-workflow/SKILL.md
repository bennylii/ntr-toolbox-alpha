# 质检工作流（NTR Daemon）

## 数据含义
`quality_report` / `check` 输出的七个码，逐对（原文行 ↔ 译文行）判定：

| 码 | 含义 | 常见原因 | 处理 |
|---|---|---|---|
| `LINE_COUNT_MISMATCH` | 缺译/行数不符 | 章节没翻完、译文缺失标记 | 补翻（expire 档） |
| `FOREIGN_CHAR_RESIDUE` | 译文里残留假名 | 漏译整段、模型直抄原文 | 重译该段；疑似整章则整章重跑 |
| `SIMILARITY` | 译文≈原文 | 同上 | 同上 |
| `GLOSSARY` | 术语未落地 | 术语表后加的 / 译名不一致 | 先看 `list_proposals` 与该术语在 `read_translations` 的出现；必要时让队列/修句处理 |
| `PUNCTUATION_MISMATCH` | 句末标点/引号不一致 | 模型输出风格 | 轻量问题，优先级低；同一章大量出现才处理 |
| `TEXT_PRESERVE` | 保留段（标签/控制码）缺失 | 翻译时丢了占位符 | 重译该段，确认处理链规则 |
| `RETRY_THRESHOLD` | 该章翻译时重试 ≥2 次 | 上游不稳/原文难 | 人工看一眼译文即可，不一定要动 |

## 处理原则
1. **先定位再动手**：用 `read_translations` 取命中样例的上下文，确认是个别行还是整章问题；
2. 个别行 → 修句链路（生成修正提案，人工确认后写回）；整章 → 重跑该章；
3. 术语类问题 → 回到术语工作流（先证据后写入，走审批）；
4. 报告里可以只挑重点码汇报，不要把七码全倒给用户。

## 边界
- 质检本身只读，不改任何数据；修复动作都要经过审批或提案；
- 不要为了让报告好看而放宽判定（阈值改动属设置变更，先问用户）。
