# 翻译工作流（NTR Daemon）

## 何时用
- "把这本书没翻的章节补上"、"重跑过期译文"；
- 长时间没动、或上次翻译失败想知道原因。

## 只读侦察
1. `list_books` / `book_status`：看已译章数、最近 run 的 `stats`（目标/上传/失败/跳过）与 state；
2. `read_translations { book, offset, limit }` 抽查已有译文质量；
3. 需要时 `quality_report` 看七码分布，判断是"没翻"还是"翻了但有问题"。

## 推进方式
- 补翻：按档位跑翻译（`expire` = 未译或术语表已更新；`normal` = 只补未译；`all` = 全量重跑），可选限章数小步快跑；
- 失败章节：先看 run stats 里的 `failures[].error`（缺凭据/上游限流/段落数不匹配各处理方式不同）；上游限流会自动冷却重试，不要催促连续重跑；
- 术语表刚改过 → 相关章节会变"过期"，用 `expire` 档补翻即可。

## 边界
- 不改站点原文；译文写回由翻译管线负责（段落数必须与原文一致）；
- 翻译用异步/长任务：触发后回报 job 状态，不要空等；用户可随时中止。
- 单线程上游（逆向 Gemini 等）排队是正常现象，不要用并发参数硬顶。
